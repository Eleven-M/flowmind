# FlowMind 2.1.1

FlowMind 2.1.1 improves MCP call reliability, skill error resilience, developer extensibility, and routing intelligence.

## Highlights

- MCP tool calls now retry automatically with exponential backoff and jitter on transient failures (network errors, timeouts, HTTP 429/5xx), while MCP business errors and HTTP 4xx are never retried.
- Six skills that depend on external MCP or filesystem operations now return structured error results instead of throwing unhandled rejections.
- New `flowmind skill create <name>` CLI subcommand scaffolds a new skill with `SKILL.md`, `index.js`, trigger patterns, and component dependencies in seconds.
- Learned skill routing now weighs frequency, recency, and correction history so the most-used and recently active routes win ties while repeatedly misrouted inputs are suppressed.

## What Changed

### MCP Client Retry (`core/mcp-http-client.js`, `core/adapters/mcp-adapter.js`)

- `callMcpTool` accepts `maxRetries` (default 2) and `retryDelay` (default 1000ms) and retries on transient errors.
- Exponential backoff with ±30% jitter prevents thundering-herd retries.
- Every error now carries a structured `error.code`:
  - `MCP_TIMEOUT` — AbortController timeout (retryable)
  - `MCP_NETWORK_ERROR` — fetch TypeError / DNS / connection refused (retryable)
  - `MCP_RATE_LIMIT` — HTTP 429 (retryable)
  - `MCP_HTTP_5XX` — HTTP 5xx (retryable)
  - `MCP_HTTP_4XX` — HTTP 4xx other than 429 (not retryable)
  - `MCP_PARSE_ERROR` — invalid JSON response (not retryable)
  - `MCP_TRANSPORT_MISSING` — URL not configured (not retryable)
- MCP JSON-RPC `payload.error` responses preserve the server-provided code and are not retried.
- `McpAdapter.callTool()` forwards `transport.maxRetries` and `transport.retryDelay` so adapters and the auto-flow skill (which calls `callMcpTool` directly) are both covered.

### Skill Error Wrapping (`core/skill-error-wrapper.js` + 6 skills)

- New `wrapSkillCall(skillName, input, operation, options)` helper catches failures from MCP and filesystem calls and returns a `createSkillError` result with `retryable`, `errorCode`, and `bindingHint`.
- `isRetryableError(error)` classifies errors using the new MCP error codes.
- Wrapped skills and their operation branches:

  | Skill | Wrapped branches |
  |-------|-------------------|
  | `data-logic-validation` | SQL execution, Redis operations |
  | `knowledge-ops` | search, list, save (readFile + createDoc), update (readFile + updateDoc), template (writeFile) |
  | `report-insights` | coverage / test / build query block |
  | `resource-bind` | list, status, bind (saveResourceBinding) |
  | `yapi-sync-interface` | search, list, export, import (readFile + importSwagger) |
  | `yuque-sync-design` | search, list, sync (readFile + createDoc) |

- Pre-validation checks (missing-component, missing-parameter, invalid-input) are intentionally left unwrapped since they do not involve external calls.

### Skill Scaffold Command (`core/skill-scaffold.js`, `bin/flowmind.js`)

- `flowmind skill create <name>` is a proper commander subcommand of `skill`.
- Interactive prompts collect description, category, trigger patterns, and component dependencies using `inquirer`.
- Flags (`-d`, `-c`, `-t`, `--components`, `--no-interactive`) support non-interactive usage for scripting.
- Generated `index.js` includes `wrapSkillCall`, `createSkillError`, and `createSkillResult` imports so new skills follow the same error-handling pattern from the start.
- Name validation enforces lowercase kebab-case matching existing skill names.

### Learning Engine Routing Enhancement (`core/learning-engine.js`)

- `matchSkillRoute` scoring formula:

  ```
  finalScore = max((baseScore + frequencyBoost) * decayMultiplier - correctionPenalty, 0)
  ```

- **Frequency boost**: `min(useCount * 0.02, 0.1)` — each use adds 0.02 up to a 0.1 cap.
- **Temporal decay**: `0.85 + 0.15 * exp(-ageInDays / 90)` — 90-day half-life with an 85% floor so stale routes are de-prioritized, not erased.
- **Correction penalty**: `min(correctionCount * 0.1, 0.3)` — three corrections suppress even an exact match below the fuzzy threshold.
- `learnSkillRoute` records `correctionCount` and `lastCorrected` when the same normalized input's target skill changes.
- The 0.72 Dice threshold for fuzzy matches is unchanged; frequency boost is pure gain and cannot rescue an unrelated route.
- Routes without a `stats` object (legacy data) continue to work via `Number() || 0` fallbacks.

## Safety and Compatibility

- MCP retries default to `maxRetries=2` — conservative because MCP tools may have side effects (deployments, data writes). Configure via `transport.maxRetries` and `transport.retryDelay`.
- Existing `skill <name>` command behavior is unchanged; `skill create` is a subcommand that does not interfere with the parent action.
- Learning data format is backward compatible — `correctionCount` and `lastCorrected` default to 0/undefined on existing routes.
- Runtime support remains Node.js 18 and newer.
- All 295 tests pass (232 existing + 63 new).
